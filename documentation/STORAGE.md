# Storage plan
| What | Where | In Git? |
|---|---|---|
| Engine code, manifests, transcripts, plans, status, QA reports (JSON/MD), memory | repository | Yes |
| Original recordings | `media/originals/` (read-only) | No (private, large) |
| Working audio | `public/audio/` | No (regenerated by ingest) |
| Renders, chunks, deliverables | `renders/`, `deliverables/` | No |
| QA frame images | `quality-reports/**/frames/` | No (contact sheets are kept) |

Repository must be **private** (course recordings and transcripts are LifeLink IP).
Options for media persistence, simplest first (none configured yet, client decision needed):
1. Keep originals on your own computer/Drive; re-upload when a lesson needs work. Renders are downloaded as deliverables. (No setup, $0.)
2. Git LFS in the private GitHub repo: GitHub's free LFS quota is small (about 1 GB), so it suits audio only. Video needs a paid data pack.
3. A cloud bucket (e.g. Google Cloud Storage / S3) with an access key: scalable, low cost, but needs an account and a key saved as an environment secret.
